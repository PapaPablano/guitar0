Grounding Context

Codebase Context

Tab Highway shows one song in five switchable views: the note highway, the tab strip, the fretboard, and the photographic neck and pick views, plus a slim bar timeline that appears when no panel is the tab strip. Two panels show at once (a top and a bottom slot). Every on-page canvas draws from one clock time per animation frame, so the views are already in step in time. They are not yet in step in how they look.

  • Different "now" markers. The highway pins the sounding gem to a white strikeline at 18% of its width. The tab strip uses a yellow cursor behind a fixed clef gutter. The bar timeline uses the same yellow, with no shared colour token. Both yellow lines hardcode #ffd43b (src/render/tab-strip.ts:300, src/render/bar-timeline.ts:154).
  • Different verdicts on "what is sounding". The highway adds a 0.3 s hold, a layout helper uses t < endSeconds, the neck cues use t <= endSeconds plus a linger, and the fretboard holds the last started step until the next one starts. The verifier counted at least five definitions.
  • Look-ahead means different things. "Notes ahead" (1 to 8 groups, default 4) reaches the fretboard and neck but not the highway, which keeps a fixed 3 s window (src/app/panel-draw.ts:37 passes it no options).
  • Different time axes. The highway is linear in seconds. The tab strip now spaces notes by note value. The fretboard and neck have no time axis at all. The same moment is at a different x in each.
  • Page, fullscreen and export disagree. The export duplicates the panel switch and hardcodes its background (src/render/stage-frame.ts:70,78). Fullscreen shows the bar strip only for the fretboard (src/app/PanelFullscreen.tsx:65), while the page and export show it whenever no panel is the tab strip.
  • Interaction stops at the tab canvas. Click-to-seek and drag-to-loop are limited to the tab strip (Stage.tsx:86). No hover or selection state is shared between views.
  • Colour. Nobody passes a theme, so every view falls back to DEFAULT_THEME. The fretboard, neck and calibration each carry their own palette. An earlier plan notes that changing canvas colours changes exported video.

External context

Moderate confidence; a few searches only. Soundslice drives every view from one clock, lights notes in notation and fretboard together, makes every view a seek control, and snaps loops to note or bar boundaries. Rocksmith reuses one string-colour mapping across its highway and on-screen guitar, backs colour with height cues, and players complain notes blend into the string colour at the strike line. Nothing found shows a photographic neck view or one visual language shared across five views.

Ranked Ideas

Seven survivors from about 40 raw ideas (19 merged candidates, 7 kept). One fresh-context verifier checked the bases against the code and confirmed every file:line quote it spot-checked. Ideas 1 to 4 are the sync foundation; 5 to 7 build on it.

  1. One Moment object for every view
  2. One "now" language: shared colour roles and marker
  3. One look-ahead that every view honours
  4. One stage renderer for page, fullscreen and export
  5. One note lifecycle with a next-note cue everywhere
  6. Seek and loop from any view
  7. Strikeline as fretboard: when and where in one place

1. One Moment object for every view

Axis 1: now and the note to playConfidence 90%Complexity Medium

Description
Build one frozen Moment per animation frame in the stage, the fullscreen view and the export: time, playback bar, sounding notes per track, the next step, loop range and look-ahead. Pass it to every draw function so no view re-derives what is sounding or upcoming. The hold, linger and inclusive-versus-exclusive rules collapse into one definition. Add a parity test that renders every view at fixed moments and checks they agree.
Basis
direct: highway.ts:116 uses emphasisAt(...).sounding with a 0.3 s hold (emphasis.ts:8); layout.ts:57-59 isActive is t < endSeconds; neck-cue-model.ts:135 uses <= endSeconds and :150 adds a linger; fretboard-steps.ts:11 keeps the last started step until the next one starts. The verifier counted five divergent rules. Stage.tsx and PanelFullscreen.tsx each already have one place that calls drawSurface.
Rationale
Sync is the user's ask, and today the views share the clock but not the verdict, so a note can be lit in one view and finished in another at exactly the instant the eye is checking. Ideas 2, 3, 5 and 7 all read from the Moment, so it makes each of them cheap.
Downsides
It changes the draw signature for every view and changes how "sounding" feels in some of them (a one-time behaviour change the team has to accept). It is the riskiest idea to land last, which is why it ranks first.

2. One "now" language: shared colour roles and marker

Axis 3: colour and visual languageConfidence 85%Complexity Low

Description
Add role tokens to theme.ts (NOW, NEXT, SOUNDING, LOOP, BACKGROUND), kept out of the six string colours so a string colour only ever means "which string". Replace the white strikeline, the two hardcoded yellows and the export background with them, and draw the three markers with one helper (same weight, glow and cap). Give any note touching the marker a luminance-safe outline so it cannot vanish into its own string colour.
Basis
direct: tab-strip.ts:300 and bar-timeline.ts:154 both hardcode '#ffd43b'; the highway strikeline is separate (highway.ts:107-108); stage-frame.ts:70 hardcodes '#101216'; nobody passes a theme, so everything falls back to DEFAULT_THEME. external: Rocksmith players report notes blending into the string colour at the strike line (web research, moderate confidence); aviation displays reserve colours by meaning, not by data series.
Rationale
The eye learns one symbol for "this instant" and finds it in whichever two panels are showing. It is the cheapest change that is visible on every screen, and it makes a high-contrast or colour-blind mode one edit later.
Downsides
An earlier layout plan flagged that changing canvas colours changes exported video, so this needs an explicit decision (or an opt-in version) on whether exports may change. The contrast outline is a design call that needs a look at real string colours.

3. One look-ahead that every view honours

Axis 2: time scales and look-aheadConfidence 80%Complexity Medium

Description
Make "Notes ahead" one app-wide quantity (a number of note groups, with the equivalent seconds at the current tempo, clamped so fast passages stay readable). The highway window, the tab strip's visible span and the fretboard and neck steps all derive from it. Each view draws a faint horizon edge where "ahead" ends, and the bar timeline can bracket the span each view currently shows.
Basis
direct: layout.ts:24 sets DEFAULT_LOOKAHEAD_SECONDS = 3; panel-draw.ts:37 calls renderHighway(...) with no options while :43 passes lookahead to the fretboard; fretboard-steps.ts:19-21 bounds steps at 1 to 8, default 4. external: map locator insets and overview-plus-detail interfaces show what a detail view covers.
Rationale
A player who lowers "Notes ahead" to 2 for a hard passage today still sees a flood of notes on the highway, so the setting silently fails on the view they are most likely to be watching.
It forces one decision worth having: whether look-ahead is measured in notes or in time.
Downsides
Notes and seconds do not convert cleanly; the mapping has to adapt to tempo and could make the highway window jump on tempo changes. Export captures look-ahead at export start and would need the same treatment.

4. One stage renderer for page, fullscreen and export

Axis 4: layout, focus and exportConfidence 85%Complexity Medium

Description
Have the export call drawSurface instead of its own copy of the panel switch, and move the "when does the bar strip show" rule into one function used by the page, fullscreen and export. What the player tunes on screen is then what they get in the video, and every sync change lands once instead of three times.
Basis
direct: stage-frame.ts:78 calls renderHighway directly and :108 draws the bar strip with only time and loop; PanelFullscreen.tsx:65 has withBar = panel === 'fretboard' while stage-layout.ts:68 needsBarStrip (tested at stage-layout.test.ts:73-77) shows it whenever no panel is the tab.
Rationale
It is the precondition for shipping any export-visible sync change safely, and it removes a standing source of drift.
The part worth a team decision is the single bar-strip rule, since the three surfaces disagree today.
Downsides
Largely a refactor, so low novelty on its own; the export's equal-height split and slim-strip geometry may need care so the video does not change shape.

5. One note lifecycle with a next-note cue everywhere

Axis 1: now and the note to playConfidence 65%Complexity Medium

Description
Define one note envelope (upcoming, next, sounding, released) with fixed timings, drawn with one visual grammar in every view: a ring that tightens on the next note, a fill while it sounds, a short afterimage when it ends. The highway gem, the tab fret number, the fretboard halo and the neck dot become the same gesture in different geometry. The highway and tab strip gain the next-note cue they lack today.
Basis
direct: fretboard.ts:148 "The next marker swells as its moment nears."; fretboard-steps.ts:13 exposes upcoming, nearest first; the highway pins the sounding gem with const cx = e.sounding ? layout.strikeX : noteX(layout, note, t). external: karaoke wipes and VU-meter ballistics (one envelope across very different displays; analogy only).
Rationale
The same moment currently lights for different durations in different panels, which the eye reads as lag. One envelope means "this note is happening" looks the same wherever the player looks, and shows how long the note has left.
Downsides
Depends on idea 1. It is a visual-language call that needs prototyping on real songs, and extra rings add clutter to dense passages. A shared beat pulse was considered and left out as polish.

6. Seek and loop from any view

Axis 5: cross-view interactionConfidence 65%Complexity Medium

Description
Extend click-to-seek and drag-to-loop beyond the tab canvas to the bar timeline and the other views that have a meaningful position (the highway by time, the fretboard and neck by step). Draw the loop with one shared tint everywhere so a loop set in one panel is visible in all. Linked hover (a ghost "now" in the other views) is a possible follow-up, not part of this idea.
Basis
direct: Stage.tsx:86 has const seekable = id === 'tab', and the interaction scout found no shared hover or selection state in the render layer; the shared use-bar-select hook already does the work for the tab. external: Soundslice makes every view a seek control and snaps loops to note or barline.
Rationale
Interaction is part of "reads as one picture": if the player can only navigate from one view, the others stay passive. It is the only idea on this axis, so it keeps the survivor set across all five axes.
Downsides
The photo views may not hit-test cleanly, and clicks on the highway currently toggle play, so the gesture needs a decision. The verifier rated the bundled hover idea weak, so only the seek and loop half was kept.

7. Strikeline as fretboard: when and where in one place

Axis 1: now and the note to playConfidence 45%Complexity High

Description
At the highway's strikeline, draw the six strings with the fret numbers so an arriving gem lands on its string at the right fret, in the NOW colour. The fretboard's sounding state becomes the same marker, mirrored. The highway then shows where the hands go as well as when, at the one point the eye is already fixed on.
Basis
external: Rocksmith reuses one string-colour mapping across its highway and on-screen guitar, but players report notes blending into the string colour at the strike line, which a distinct landing zone avoids. reasoned: the highway already has a strikeline and string lanes, and the fretboard already has a sounding halo, so the two "now" points can be merged rather than kept as separate panels.
Rationale
It is the one idea here that is a visible differentiator rather than consistency work: it merges the "when" view and the "where" view at the point of attention.
Downsides
Changes what the highway is. A strikeline carrying fret numbers on six lanes is dense and may clash with the existing neck and fretboard panels. Needs a throwaway prototype before any commitment.

Rejection Summary

About 33 of the raw ideas merged into the survivors above (the five convergent clusters in ideas 1 to 4 and the next-note, beat-pulse and horizon-bracket variants). The rest were considered and cut:

#IdeaReason rejected
1One literal "now" column across stacked panels, with a shared rulerThe tab strip's clef gutter and different panel widths force different x positions, so a single column conflicts with the layout; the useful part (the marker looks the same everywhere) is in idea 2.
2Shared beat pulse on every now markerPolish with little legibility gain, and it fails the meeting test alone; it can be added as a field of the Moment later.
3Bar timeline playhead uses the tab strip's note-anchor mappingSound and cheap, but bug-fix sized rather than a direction; it rides along as an early consumer of idea 1.
4Golden-moment parity test harnessAn engineering enabler rather than a product idea; folded into idea 1 as its verification plan.
5Auto-pair layout ("Follow" mode)Takes layout control away from the user and is mostly subsumed by idea 4's single rule.
6Single-stage mode with the other views as ghosts, and layers instead of panelsSpeculative redesigns with no repo basis beyond "two slots"; the premise that the eye jumping between panels is the pain is unverified. Better framed as an experiment than an idea.
7Time-scale morph slider between linear and note-value spacingSpeculative control that adds complexity; the useful part is the mapping fix in rejection 3.
8Focus panel with peripheral rendering for the othersBasis is purely reasoned and unverified, and degrading the other views works against syncing all of them.
9Neck and pick camera easing tied to the highway's timeThin basis ("arrives as the gem reaches the strikeline" is not grounded) and depends on ideas 1 and 3.
10Persistent "scorebug" readout stripA new feature whose repo basis is only the bar-strip divergence that idea 4 already covers.
11Overview-plus-detail brackets on the bar timelineDuplicates idea 3; kept there as an optional visual device.
12Linked hover and ghost playhead skimmingVerifier rated it weak: speculative and separable from seek and loop; left as a follow-up to idea 6.
13Bundles of ideas 1, 3 and 6 (aligned time, linked navigation)Scope beyond what the evidence supports; their solid parts survive as ideas 3 and 6.

No axis ended with zero survivors, so there is no coverage gap to record. Verification budgets were per agent and not uniform: one generation agent opened three files, several opened none, so bases tagged direct: are verified only where the verifier or the agent read the line.
